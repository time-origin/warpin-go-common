# 第三方登录平台申请与联调资料清单

版本：v1.0
日期：2026-09-03
接收方：业务、法务、产品及移动端负责人

## 1. 目的

为 VoiceCraft 移动 App 申请微信、抖音和小红书第三方登录能力。本文件只记录申请项和交付方式，不得填写或传播真实密钥。

## 2. 开始申请前需要准备

- 企业主体全称、统一社会信用代码、营业执照及管理员身份材料。
- 应用中文名、英文名、简介、应用图标和功能截图。
- Android 包名、正式签名指纹及计划上架的应用市场信息。
- iOS Bundle ID、Apple Team ID、Universal Link 域名。
- 已备案的 HTTPS 官网、隐私政策、用户协议、账号注销说明和客服联系方式。
- 生产、测试环境清单及对应回调地址；不得把测试环境与生产环境共用密钥。
- “第三方登录用于创建/访问 VoiceCraft 账号”的产品说明及授权页面截图。

## 3. 微信开放平台

### 3.1 业务侧办理事项

1. 注册并认证微信开放平台企业开发者账号。
2. 创建“移动应用”，分别登记 Android 和 iOS 信息。
3. 申请“微信登录”能力并完成平台审核。
4. 配置 Android 包名与应用签名、iOS Bundle ID 与 Universal Link。
5. 确认是否能够返回 `unionid`，以及多个应用是否归属同一微信开放平台主体。

### 3.2 需要交付研发

| 项目 | 是否敏感 | 交付对象 |
|---|---:|---|
| AppID | 否 | 移动端、服务端 |
| AppSecret | 是 | 仅服务端密钥管理员 |
| Android 包名和签名 | 否 | 移动端 |
| iOS Bundle ID、Universal Link | 否 | 移动端、服务端 |
| 已批准的 scope | 否 | 移动端、服务端 |
| 测试账号与审核状态 | 受控 | 联调负责人 |

官方文档：<https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html>

## 4. 抖音开放平台

### 4.1 业务侧办理事项

1. 入驻并认证抖音开放平台企业开发者。
2. 创建“移动应用”，登记应用名称、类别、Android/iOS 包信息。
3. 申请并确认 `user_info` 登录授权能力。
4. 完善官网和隐私材料；商用前完成应用上线转正。
5. 如同时接入分享，单独确认分享权限，不能默认登录权限包含发布权限。
6. 为测试和生产环境分别确认可用的应用及凭证，避免相互覆盖 token。

| 已批准的 scope，至少确认 `user_info` | 否 | 移动端、服务端 |
| 授权回调地址（如使用 Web 授权） | 否 | 服务端、平台控制台管理员 |

## 5. 小红书

小红书账号开放平台已提供 OAuth 2.0 登录、PKCE、授权码换 token 和用户基本信息接口。该能力与 `agora.xiaohongshu.com` 的分享开放平台是两套独立能力，需要分别申请。

### 5.1 业务侧办理事项

1. 在小红书账号开放平台创建并审核移动应用。
2. 申请首期 `basic_info` scope。
3. 分别申请 Beta 和生产环境凭证；两套环境的 `app_id/app_secret` 不通用。
4. 登记 Android 包名、签名以及 iOS Bundle ID、URL Scheme/Universal Link。
5. 与研发确认使用模式：本项目有服务端，默认由服务端持有 `app_secret` 并换 token；如移动端采用 PKCE，则同时交付 `code_verifier`。
6. 确认账号解除授权、数据删除、隐私披露和技术支持渠道。

### 5.2 需要交付研发

| 项目 | 是否敏感 | 交付对象 |
|---|---:|---|
| Beta App ID | 否 | 移动端、服务端 |
| Beta App Secret | 是 | 仅服务端密钥管理员 |
| Production App ID | 否 | 移动端、服务端 |
| Production App Secret | 是 | 仅服务端密钥管理员 |
| 已批准的 `basic_info` scope | 否 | 移动端、服务端 |
| Android/iOS 应用登记信息 | 否 | 移动端 |
| Secret/PKCE 模式决定 | 否 | 移动端、服务端 |
| 审核状态与对接群 | 受控 | 联调负责人 |

## 6. iOS 上架补充：Sign in with Apple

如果 iOS App 使用微信、抖音等第三方登录来建立用户主账号，应同步评估并办理 Sign in with Apple，以满足 App Store Review Guidelines 4.8。

需要准备：

- Apple Developer 企业团队账号和 Team ID。
- 开启 Sign in with Apple 的 App ID / Services ID。
- Key ID 与 `.p8` 私钥。
- iOS Bundle ID、Return URL、邮件中继域名配置。
- App Store 隐私披露和账号删除流程。

`.p8` 私钥属于最高敏感级别，只能交付服务端密钥管理员，不得通过聊天、邮件正文、Git 或普通文档传递。

官方文档：

- <https://developer.apple.com/app-store/review/guidelines/#login-services>
- <https://developer.apple.com/documentation/signinwithapplerestapi>

## 7. 密钥交付规则

1. 本文档、需求系统和即时聊天中只填写“已申请/待申请/负责人/到期时间”，不填写 Secret。
2. Secret 必须通过公司密码库或云 Secret Manager 交付。
3. 移动端只配置公开的 AppID、AppKey 或 Client Key，不配置 AppSecret、Client Secret 或 `.p8` 私钥。
4. 服务端通过业务仓选定的密钥机制注入，禁止写入 Git 和普通 ConfigMap。
5. 测试与生产使用不同凭证；凭证轮换后记录轮换时间，但不记录密钥明文。

具体的环境变量、Secret 路径和 Provider 开关名称由各业务仓定义，不属于公共模块合同。
