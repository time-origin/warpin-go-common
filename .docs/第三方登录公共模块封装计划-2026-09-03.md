# 第三方登录公共模块封装计划

日期：2026-09-03
状态：已确认，执行完成

## 目标

在 `warpin-go-common/auth/oauth` 中建立平台无关的第三方身份认证边界，并按官方登录文档实现微信、抖音和小红书 Provider。业务用户、账号绑定、登录意图、业务 JWT 和第三方凭证持久化继续由业务仓负责。

## 本期范围

1. 新增统一 `IdentityProvider`、`Credential`、`Identity` 和只读 `Registry`。
2. 新增稳定的公共错误分类，业务仓据此转换为自己的错误码和中文消息。
3. 实现微信移动应用授权码登录 Provider。
4. 实现抖音移动/网站应用授权码登录 Provider。
5. 小红书同时支持生产与 Beta 联调环境，以及 Secret、PKCE 两种换 token 模式。
6. 保留现有 Google、GitHub API 的兼容性，不在本期扩展其能力。
7. 不在公共仓保存 access token、refresh token、用户或业务 JWT。

## 注入边界

- 公共模块的编码、测试和发版不依赖任何平台真实凭证。
- Provider `Config` 只是构造入参，不读取环境变量、配置文件或密钥管理系统。
- AppID/AppKey/AppSecret 由业务仓在运行时注入；公共模块不定义业务仓的环境变量名或开关策略。
- 业务仓可在实际凭证到位前完成代码接入；真实凭证只是联调和上线的前置条件。

## 安全约束

- AppSecret/ClientSecret 只通过构造参数由调用方注入，不写入源码、日志或错误。
- Provider 使用固定官方 HTTPS 端点。
- 所有 HTTP 请求继承调用方 context，并使用带超时的 HTTP Client。
- 限制响应体大小，不把上游响应体透传给调用方。
- 授权码为空、过期或已使用时返回可识别的无效凭证错误。
- AppID、密钥或平台权限错误返回配置错误。
- 上游网络及服务异常返回平台不可用错误。
- Registry 在启动时构建，拒绝空名称和重复 Provider。

## 验证

```bash
go test ./...
go test -race ./...
go vet ./...
```

Provider 测试使用自定义 `http.RoundTripper` 模拟官方接口，不使用真实账号或密钥。

## 实施结果

- `auth/oauth/provider.go`：统一凭证、身份、Provider 接口和错误分类。
- `auth/oauth/registry.go`：不可变 Provider 注册表。
- `auth/oauth/wechat`：微信授权码换 token 和用户信息标准化。
- `auth/oauth/douyin`：抖音授权码换 token 和用户信息标准化。
- `auth/oauth/xiaohongshu`：小红书生产/Beta、Secret/PKCE 登录和用户信息标准化。
- 三个 Provider 都只返回标准身份，不返回第三方 token。
